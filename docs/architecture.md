# Архитектура и API

## Компоненты

| Файл | Назначение |
| --- | --- |
| `sofa.lua` | HTTP-сервер, авторизация, статические файлы, команды плеера |
| `tracker.lua` | Независимый цикл учёта просмотра и автопереходов, 0,5 секунды |
| `library.lua` | Распознавание серий, объединённый каталог, постоянные ID |
| `navigation.lua` | Общие параметры запуска серий и синхронизация обычной очереди VLC |
| `progress.lua` | Чистая логика интервалов, закладок и завершённости |
| `markers.lua` | Проверка таймингов и однократное планирование переходов |
| `audio.lua`, `audio.m` | Ограниченный мост к свойствам текущего выхода CoreAudio |
| `web/` | Мобильный интерфейс без внешних сервисов и библиотек |
| `sofa.py` | Установка, каталог, диагностика, манифесты |
| `tools/frames.py` | Кадры из видео с ограниченной нагрузкой, без управления VLC |

VLC загружает два Lua-интерфейса через `extraintf`. Вспомогательный бинарник запускается только для чтения/изменения свойств аудиовыхода, с лимитом 2 секунды. Системная громкость опрашивается с кэшем 2 секунды. Постоянного внешнего сервера и launchd-службы нет.

## Каталоги и совместимость

Приватный `libraries.json`:

```json
{
  "version": 1,
  "revision": "случайный идентификатор изменения",
  "libraries": [
    {"id": "show-example", "title": "Пример", "root": "/путь/к/Примеру"}
  ]
}
```

Глобальный ключ эпизода — `show-example:s01e01`. Манифест внутри сериала использует локальный ключ `s01e01`. Старые настройки `libraryRoot` / `libraryTitle` читаются как сериал `legacy`; его ключи прогресса остаются прежними (`s01e01`). Первая команда `add` сохраняет эту совместимость в реестре, не переписывая историю.

Каталог перечитывает реестр сразу при HTTP-запросе и примерно раз в секунду в трекере. Файлы внутри существующих папок сканируются раз в 30 секунд. Python и Lua распознают одинаковые основные шаблоны; дубликаты исключаются. Следующая серия выбирается только внутри того же сериала.

Трекер синхронизирует обычную очередь VLC при смене текущего элемента или каталога. Очередь содержит только доступные серии текущего сериала; прежние элементы и дубликаты удаляются. Текущий элемент сохраняет ID, позицию и состояние паузы. `playlist.clear()` не используется. Для сортировки элементы перемещаются в начало корня в обратном порядке: в VLC 3 перемещение после другого элемента зависит от арифметики ID и ненадёжно после удалений.

Остальные элементы очереди получают `start-time` из актуальной истории. Для предыдущих серий сохраняется закладка даже у завершённых; для следующих завершённая серия запускается сначала. При смене серии закладки оставшихся элементов обновляются, поэтому штатные Next/Previous и аппаратные клавиши используют тот же порядок и прогресс, что пульт. Возврат назад прямо в титры подавляет повторный автопереход в рамках этого захода. Случайный порядок и циклическое воспроизведение для управляемой очереди отключаются. Файлы вне каталога не синхронизируются.

`progress.json` сохраняется атомарно примерно раз в 2 секунды, при смене серии и паузе. `.bak` содержит предыдущую корректную запись. При повреждении обеих копий трекер отказывается заменять историю пустой. Индексатор и HTTP-интерфейс историю не записывают.

## HTTP

`GET /health` возвращает `service`, `version` и `apiVersion: 2`, без данных просмотра. Для остальных данных: `POST /api`, `Content-Type: application/json`.

```json
{"action":"login","pattern":"выбранные-ключи-картинок"}
```

Ответ содержит `token` и `status`. Передавай `token` во всех последующих запросах. Для команд изменения добавляй уникальный `requestId`; повтор того же запроса не выполняет действие второй раз.

| Действие | Дополнительные поля |
| --- | --- |
| `status` | — |
| `library` | необязательный `seriesId` |
| `logout` | — |
| `toggle`, `mute`, `fullscreen`, `next`, `previous` | `requestId` |
| `seek` | `delta`: только −5 или 5 |
| `play_episode` | `id`, необязательный `fromStart` |
| `volume` | `value`: ограничивается 0–200 |
| `volume_step` | `delta`: −5 или 5 |
| `system_volume` | `deviceId`, целый `value`: 0–100 |
| `system_volume_step` | `deviceId`, `delta`: −5 или 5 |
| `system_mute` | `deviceId`, `value`: 0 или 1 |
| `audio`, `subtitle` | `value`: ID из текущего статуса |
| `playback_preferences` | `key`: `skipIntro` / `nextEpisode`, булев `value` |

Старая команда `scrub` всегда отклоняется: таймлайн только для просмотра. `library` возвращает список `series`, выбранный `seriesId`, доступные `seasons`, `episodes` и `continueId` для выбранного сериала. Смена просматриваемого каталога не меняет воспроизведение.

`previous` выбирает предыдущую доступную серию того же сериала и возобновляет её с закладки. На границах каталога `next` / `previous` возвращают `last_episode` / `first_episode`; для файлов вне каталога используются стандартные команды VLC.

В VLC 3 аппаратные Next/Previous циклически обходят очередь даже при отключённом loop. Этот штатный обход остаётся внутри выбранного сериала. Автоматическое завершение последнего файла останавливает воспроизведение.

Сервер проверяет Host и Origin, ограничивает размер запроса, статические пути и число соединений. Сеансы имеют срок жизни 30 дней, не более 24 сохранённых; после пяти неверных комбинаций вход блокируется на 30 секунд. Это простая защита домашнего пульта, не публичный интернет-сервис.

## Обновления

Код Lua загружается при старте интерфейса. Статические файлы читаются по запросу; `Cache-Control: no-store` позволяет обновить UI перезагрузкой страницы. JSON-каталоги и манифесты публикуются атомарно и перечитываются автоматически. Во время просмотра установщик `--stage` не меняет `vlcrc` и не перезапускает VLC.

Исходники не содержат личного состояния. Бинарник `sofa-audio` собирается на машине установки. Для сохранения баланса каналов используется virtual main volume, с fallback на master scalar. Перед записью проверяется прежний device ID; смена HDMI на наушники не должна направлять старую команду в новое устройство.
